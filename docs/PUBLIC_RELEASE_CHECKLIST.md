# GoodAgent Publication Checklist

This checklist is not publication approval. There are two different milestones:
an **experimental source disclosure** and a **qualified self-hosted alpha**.
Source disclosure may be approved before qualification is complete, but it must
state incomplete work and failed gates honestly. Neither milestone authorizes a
hosted service, announcements, packages, container images or real commerce writes.

## Experimental Source Disclosure

- [ ] Confirm the separate destination and its private visibility through an
      authorized connection. A configured local remote is not verification.
- [ ] Preserve the original private repository, history, stores and historical
      release/security evidence. Do not retarget an existing RC or final tag.
- [ ] Inspect the exact history-free export, its manifest and all included files.
      Exclude credentials, personal data, conversations, private review transcripts,
      unrelated documents and unreviewed redistribution assets.
- [ ] Verify Apache-2.0, NOTICE, third-party notices, sample/image attribution and
      the owner's truthful DCO sign-off. No CLA or license change is implied.
- [ ] Keep original provenance privately. Record actual preparation times, author,
      exact commit and source/manifest hashes; do not backdate history.
- [ ] Review README claims, local links and media for the exact staged tree.
      Disclose Basic mode, synthetic sample values, demo checkout, model costs,
      local-only deployment limits and unfinished capabilities.
- [ ] Include an accurate status of tests, scans, HIGH/CRITICAL findings, expired
      assessments and incomplete demonstrations. Do not hide or disable failing
      gates to make a source-only snapshot look qualified.
- [ ] Review the public CI substitution, initial-commit DCO checks, fork safety,
      logs and artifact-upload paths. Use synthetic fixtures and no store/model
      credentials. Keep the original private CI and protections unchanged.
- [ ] Present the exact separate repository, commit, export manifest, evidence and
      limitations to the owner. Obtain explicit approval before changing visibility.

Follow [source export instructions](PUBLIC_SOURCE_EXPORT.md). The current
[validation status](ALPHA_VALIDATION.md) distinguishes recorded sources and failed
gates; it is not a certificate for later edits. The proposed public project name is
GoodAgent, but name selection is not trademark clearance.

## After Exact-Candidate Approval

- [ ] Change visibility only for the approved separate repository; keep the
      original repository private. Verify actual visibility afterward.
- [ ] Test an anonymous clone and public README/media rendering. Record the
      observed publication time in UTC, exact remote commit and manifest hash.
- [ ] Configure and verify applicable review, DCO, required-check, up-to-date,
      conversation-resolution, no-force-push, no-deletion and no-bypass protections.
      Report unavailable protection features rather than claiming enforcement.
- [ ] Verify security-reporting instructions and an owner-approved reporting
      contact. Enable private vulnerability reporting only with its separate
      authorization and verify the intended reporting path.
- [ ] Record any failed CI and open qualification blockers visibly. An unchecked
      box is not a waiver or accepted risk.

Tags, GitHub Releases, announcements and package/container publication require
their own authorization. Do not create a final `v0.1.0` tag as part of disclosure.
An observed disclosure timestamp documents availability, not a legal determination
of invention ownership or employment obligations.

## Qualified Alpha Follow-Up

- [ ] Freeze the exact candidate and independently review the complete changed
      source. Re-run affected checks after any change.
- [ ] Verify clean Linux and macOS installation, supported dependency versions,
      repeat setup, isolated backup restoration and recovery without resetting a
      store. Report cold downloads and cache state separately from app usability.
- [ ] Pass lint, type checks, unit/contract, integration, generated-contract and
      both application smoke checks on that candidate. Retain failed attempts.
- [ ] Exercise two fresh owner-to-shopper journeys, cancellation, service/model
      unavailability, session expiration, import replacement, memory controls and
      interrupted demo checkout. Inspect desktop/mobile evidence and accessibility.
- [ ] Complete the bounded real-model evaluations and review prices, variants,
      product grounding, permissions and privacy. Readiness is not search quality.
- [ ] Complete the two planned real-model recordings with inspected captions and
      provenance. A separate Basic-mode rehearsal is not that recording pair.
- [ ] Refresh source/container scans, SBOMs, hashes and every HIGH/CRITICAL
      applicability assessment. Missing, changed, expired, untriaged or unresolved
      applicable runtime findings block qualification. Do not extend expiry by prose.
- [ ] Preserve raw findings and accepted-risk rationale, if any; never claim zero
      vulnerabilities from a passing applicability gate or a secret-only scan.
- [ ] Verify hosted checks and repository protections for the exact proposed
      revision before calling it qualified. Local tests are not hosted CI evidence.
- [ ] Obtain owner approval for the exact qualified candidate and any alpha tag.

The historical private RC checklist/evidence remains in
[release-candidate documentation](RELEASE_CANDIDATE.md). It does not qualify the
current owner/shopper application or authorize rewriting private refs.

## Metadata Proposal

Description: **Open-source AI agents for store owners and their shoppers.**

Tagline: **Empowering small businesses with AI.**

Suggested topics: `ai-agents`, `commerce`, `self-hosted`, `search`, `python`,
`typescript`, `fastapi`, `nextjs`, `qdrant`. Metadata remains unapplied until the
destination and owner approval are verified. Leave the website empty unless an
